# Source layout

The extension source is in `liquid-glass@thinkingcoding1231.gmail.com/src`.
`dist` is generated by TypeScript and is shipped with the extension, including its subdirectories.

| Module | Owns |
| --- | --- |
| `actors/` | Actor validity, allocation rescue, cached writes, coordinates and custom actor types |
| `capture/` | Desktop/background capture, UI and window clones, nested glass and capture clipping |
| `animation/` | Shared spring models, colour interpolation and frame-sync switches |
| `rendering/` | Blur buffers, pipelines, crop targets, glass extents, uniform caching and material settings |
| `diagnostics/` | Logging, the opt-in ring recorder and Looking Glass controls |
| `quickSettings/toggleStyles.ts` | Toggle discovery, native theme colours, temporary styles and their timer/signal lifetime |
| `liquidEffect.ts` | Clutter effect lifecycle, frame reuse and the existing interface used by managers |

`utils.ts` remains an explicit compatibility export list. Internal modules import directly from the owner; new functionality should not be added to the compatibility file. The diagnostic exports previously provided by `liquidEffect.ts` remain available there too.

Each renderer instance owns its buffers and pipelines. `UniformState` retains material values across shader reloads but discards pipeline-specific locations. `BlurRenderer` keeps separate downsample, intermediate and output targets so deferred paint nodes cannot form framebuffer dependency cycles. `CropPass` and `RenderPasses` release their owned references during effect cleanup; GJS-managed Cogl resources must not be manually disposed.

The compositor frame clock and diagnostic registry are shared. The last live effect releases the stage observer. The ring recorder remains off by default.

Historical rendering constraints and failure investigations are preserved in [rendering-notes.md](rendering-notes.md). The application, menu and Quick Settings managers still contain orchestration and are not yet fully decomposed.

## Verification

Build from the extension directory with `npm run build`, then run from the repository root:

```sh
node --test --test-isolation=none tests/*.test.cjs
```

The tests cover the existing dock/menu regressions, module dependency cycles, uniform write suppression, blur pass ordering, buffer allocation failure/recovery, frame reuse, material settings subscriptions, spring motion and toggle cleanup. GNOME/Clutter/Cogl are represented by explicit adapters; these tests do not replace a visual check in a real Shell session.
